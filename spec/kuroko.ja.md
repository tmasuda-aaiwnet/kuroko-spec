## 1. 目的と設計思想（参考）

Kuroko（黒子）は、映像・音声・字幕を標準のコンテナ Matroska（mkv）に収め、その**再生の進め方**
（ナビゲーションの意味）を**コントローラ（controller）**が与える、マルチメディアのコンテナ形式である。
Matroska（マトリョーシカ人形）を、黒子（人形遣い）が操る、という見立てで名づけている。

- 拡張子：**`.krk`**
- コントローラ：**`none`**（ナビゲーションの無い素の再生。第I部）と、その上に DVD-Video 互換の仮想マシンを載せた
  **`dvd-video-vm`**（第II部）、メニュー・ボタン・動作を JSON で宣言的に書く **`kuroko-tiny`**（第III部）

Kuroko は次を目的とする。

1. **映像のケイデンスを忠実に保ったまま、高い圧縮率を得る。**
   MPEG-2 は `picture_structure`・`repeat_first_field`・`top_field_first`・`progressive_frame` などのフラグで、
   インターレースや 24p のソフトテレシネ（3:2 プルダウン）を表せた。H.264・H.265・AV1 では、これを忠実に保てる
   エンコーダや道具が一般的ではなく、再符号化でハードテレシネに焼き込んだり、デインターレースしてしまったりして、
   元の表示のケイデンスが失われがちである。Kuroko は、テレシネやインターレースの情報を**メタデータとコンテナの
   タイムスタンプ**で持つことで、エンコーダに依存せず元のケイデンスで再生できるようにする。
   **途中でケイデンスが変わる映像**も再現できる。MPEG-2 ではフレームごとのフラグで、24p のフィルム（3:2 プルダウン）の
   本編の途中にインターレースの映像（ビデオ撮りの場面・ディゾルブ・字幕の焼き込みなど）が挟まる映像や、プルダウンの
   周期が途中で崩れる映像を表せた。Kuroko では、**各フレームの表示時間をタイムスタンプに、インターレースの区間を時刻の
   区間で**持つので（10.2 節）、AV1・H.264・H.265 のどれで符号化しても、同じ切り替わりをそのまま再現できる。
2. **コントローラによって、メニュー付きのマルチメディアを作れる。**
   再生の進め方をコントローラとして抽象化し、メニュー・分岐・章を持つ対話的なコンテンツを表せる。
3. **既存の素材の情報を、なるべく欠かさずに移せる。**
   章、複数の音声（言語・デュアルモノ・マルチチャンネル）、字幕、番組情報、メニューなどを取りこぼさずに運ぶ。
   それらをどう表示するかは再生器に任せるが、形式としては情報を保つ。
4. **構造が見える。**
   独自の多重化をせず、標準のコンテナ（mkv）と構造化された JSON で持つ。汎用の道具で中身をたどり、検証し、作れる。
5. **音声はフルレンジで保ち、ラウドネスの制御は再生時に任意で当てる。**
   ダイナミックレンジ圧縮や会話音量の正規化を焼き込まず、メタデータとして持つ。

これを、次の三層に分けて実現する。

1. **殻（shell）**：ZIP。OS の標準機能や既存の道具で中身を見られる。
2. **中身（payload）**：Matroska。フレームの区切り・コーデックの初期化データ・タイムスタンプ・シーク索引を任せる。
3. **コントローラ（controller）**：「どうたどって再生するか」を JSON で明示する。

まず `none` を最小の枠組みとして定め、メニューや仮想マシンなどの対話的な機能は、`none` の器の上にコントローラを
載せて足す。また、複数のタイトルが共有する本編は**1 回だけ格納**し、その境目を**継ぎ目なく**再生できる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| Kuroko ファイル | 本書に従う `.krk` ファイル。 |
| コントローラ | 再生の進め方の種別。`KUROKO.MANIFEST` の `controller` で示す。 |
| タイトル | 再生の単位。名前・音声・字幕・章を持ち、セグメントの並び（プレイリスト）で中身を指す。 |
| セグメント | 物理的なメディアの単位（`SEGMENTS/S####/`）。映像・音声・字幕の実体と、その属性（`seg.json`）を持つ。 |
| パーツ | セグメントの中を、さらに独立に符号化したファイル単位に分けたもの（10.4 節）。 |
| 論理トラック | タイトルが番号で示す音声・字幕（「音声 1」など）。 |
| 物理トラック | セグメントの実体の中の音声・字幕。論理トラックとは `source` で結ぶ（12.2 節）。 |
| ケイデンス | 映像の表示のされ方（プログレッシブ・インターレース・ソフトテレシネ）。 |
| 時刻 | 特に断らない限り、ミリ秒の数値（小数を含んでよい）。 |

## 3. 容器

Kuroko ファイルは **ZIP** である（拡張子だけが `.krk`）。

- 書き手は、**最初のエントリを `KUROKO.MANIFEST`** にしなければならない。このエントリは**無圧縮（Stored）**でなければならない。
  読み手は、ファイルを展開せずに先頭を見るだけで Kuroko と判定できる。
- 書き手は、**メディアのファイル（`.mkv`・`.spu`・`.pgs`・画像）を無圧縮（Stored）**で格納しなければならない。
  再圧縮をせず、読み手がファイルの中の位置へ直接シークできるようにするためである。
- JSON などのテキストは、Deflate で圧縮してよい。
- 4 GiB を超えるエントリ、またはエントリ数・位置がそれを要するときは、**ZIP64** を使わなければならない。
  読み手は ZIP64 を読めなければならない。
- 暗号化した ZIP を使ってはならない。
- パスの区切りは `/` とし、大文字と小文字を区別する。本書のパスは ZIP のルートからの相対パスである。
- 読み手は、本書に無いエントリを無視しなければならない（あとで足す余地を残すため）。

## 4. KUROKO.MANIFEST

形式の識別と、コントローラの種別だけを示す入口である。JSON で書く。

```json
{ "format": "kuroko", "version": 5, "controller": "none", "createdBy": "Example Authoring Tool 1.0", "comment": "…" }
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `format` | 文字列 | 必須 | 固定の `"kuroko"`。読み手は、これで Kuroko と判定する。 |
| `version` | 整数 | 必須 | レイアウトの世代（6 章）。 |
| `controller` | 文字列 | 必須 | コントローラの種別。`"none"`（第I部）・`"dvd-video-vm"`（第II部）・`"kuroko-tiny"`（第III部）。 |
| `createdBy` | 文字列 | 任意 | 作成した道具の名前など。 |
| `comment` | 文字列 | 任意 | 自由記述。書き手は符号化の条件（コーデック・品質・キーフレーム間隔など）を記してよい。環境に依存する情報（実行ファイルのパスなど）は書くべきでない。 |

- `KUROKO.MANIFEST` は、**全体を ASCII** にすべきである（参考：他がすべて ASCII のところへ 1 文字だけ非 ASCII が混ざると、
  テキストエディタが UTF-8 と判別できず、その文字だけが化けることがある）。
- 読み手は、**知らない `controller` のファイルの再生を断らなければならない**（進め方を知らないまま再生すると、
  作り手の意図と違う動きになるため）。

## 5. JSON の共通規則

- 文字コードは **UTF-8・BOM 無し**。非 ASCII の文字は `\uXXXX` に置き換えず、そのまま書くべきである。
- キーは **camelCase**（例 `pixelWidth`）。
- 読み手は、**知らないキーを無視しなければならない**。
- 本書で「任意」とした項目は省いてよい。省いたときの値は、各表の「省略時」に従う。
- **時刻と長さは、ミリ秒の数値**である（例 `12345.678`）。キーの名前は `…Ms` で終わる。基準（0 の位置）は各項目で定める。
- 時刻の区間（`[{"startMs":…, "endMs":…}]` の形）は、`startMs` を含み、`endMs` を含まない。
- **番号と位置**：
  - **番号**（`number`・`id`・`pgn`・`pgc` など、利用者や命令が名前のように呼ぶもの）は **1 始まり**。
  - **位置**（`index`・`startCell`・`entryCell`・`segCell`・`titleCellStart`・`programMap` の値など、並びの中の場所）は **0 始まり**。
  - 例外：セルの命令の番号（`commandNr`・`cellCommand`）は「0＝なし」を表すため、1 始まりの番号である。
- **言語**は **ISO 639-2 の 3 文字・小文字**（書誌コード。`"jpn"`・`"eng"`・`"fre"`）。不明なら省く。
- **パレットの色**は、24 ビットの値を **6 桁の 16 進の文字列**で書く（17 章・20 章）。

## 6. 版と互換性

### 6.1 レイアウトの世代（`version`）

| `version` | 内容 |
|---|---|
| **5** | 本書が定める形。書き手は `5` を書かなければならない。 |
| 3・4 | 旧形式（参考）。構造は 5 と同じで、番号・位置・時刻・パレット・メニューの種類・言語の書き方が違う（付録 C）。読み手は読めるとよい。 |
| 1・2 | 旧形式（参考）。容器が ZIP ではなく、本書の対象外。読み手は読まなくてよい。 |

- 読み手は、**自分が知っているより大きい `version` のファイルを開くべきでない**（あるいは、開くなら利用者に知らせる）。

### 6.2 拡張の規則

- 新しいキーを足すときは、**知らない読み手が無視しても再生が破綻しない**形にする（任意のキーとして足す）。
  この場合は `version` を上げなくてよい。
- 列挙値（例 `video.codec`）に新しい値を足すときは、その項目に定めた「知らない値のとき」の扱いに従う。
- 既存のキーの意味を変えてはならない。変える必要があるときは、別の名前のキーを足す。

# 第I部　コントローラ `none`

`none` は Kuroko の最小の枠組みで、ナビゲーションを持たない。**名前の付いたタイトルの集合**として、
「映像・音声・字幕を、正しいケイデンスで順に再生する」ことだけを定める。ほかのコントローラは、この枠組みの上に足す。

## 7. レイアウト

```
example.krk
├─ KUROKO.MANIFEST          controller: "none"
├─ CONTROL/disc.json        タイトルの一覧
├─ VIDEO/Tnn/title.json     タイトル（論理）：プレイリスト・音声・字幕・章・番組
└─ SEGMENTS/S####/          セグメント（物理）
   ├─ seg.json              メディアの属性
   ├─ av.mkv                映像＋音声（パーツを持つときは av.pNN.mkv）
   ├─ loudness/<source>.json  ラウドネス制御のゲインの変化（任意。11.2 節）
   └─ subs/                 字幕の実体（13 章）
```

- `Tnn` はタイトル番号を 2 桁以上の 10 進で表したもの（`T01`）。`S####` はセグメントの識別子で、
  `S` と 4 桁以上の 10 進で表すべきである（`S0001`）。実際のパスは `disc.json` と `title.json` が示すので、
  読み手は名前の形に頼ってはならない。
- 物理的なメディアは `SEGMENTS/` にまとめ、`title.json` は論理だけを持つ。単一の連続した内容は、
  「セグメント 1 つのプレイリスト」で表す。

## 8. CONTROL/disc.json

```json
{
  "titles": [ { "id": 1, "name": "本編", "durationMs": 1800000, "video": "VIDEO/T01" } ],
  "firstPlayback": { "title": 1, "angle": 1, "audio": 1, "subtitle": 0 }
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `titles` | 配列 | 必須 | タイトルの一覧。並びは表示順。 |
| `titles[].id` | 整数 | 必須 | タイトル番号（1 以上・ファイル内で一意）。 |
| `titles[].name` | 文字列 | 任意 | タイトルの名前。 |
| `titles[].durationMs` | 数値 | 任意 | タイトルの長さ（一覧の表示用。正は `title.json` の `timing.totalMs`）。 |
| `titles[].video` | 文字列 | 必須 | タイトルのディレクトリ（`title.json` を含む）。 |
| `firstPlayback` | オブジェクト | 任意 | 再生を始める状態（8.1 節）。 |

### 8.1 再生の開始状態（`firstPlayback`）

ファイルを最初から再生するときの、タイトル・アングル・音声・字幕を指定する。

| キー | 意味 | 省略・範囲外のとき |
|---|---|---|
| `title` | 開始タイトル（`titles[].id`） | 一覧の先頭のタイトル |
| `angle` | アングル番号（1 始まり。12.4 節） | 1 |
| `audio` | 論理音声の**番号**（`title.json` の `audio[].number`） | 先頭の音声 |
| `subtitle` | 論理字幕の**番号**（`title.json` の `subtitle[].number`）。**0＝字幕なし** | 字幕なし |

- 再生器は、指定が実体と食い違う項目（存在しないタイトル、アングル数を超える番号など）だけを既定に戻し、
  再生を断ってはならない。
- 前回の続きから再生する（レジューム）ときは、レジュームの状態を優先してよい。`firstPlayback` は「最初から」の既定である。
- 指定した論理音声がデュアルモノのときは、主音声で始めるべきである。
- `dvd-video-vm` での扱いは 15.2 節を見る。

## 9. SEGMENTS/S####/seg.json

`seg.json` は、そのセグメントの**メディアの属性の正**である。`none` のセグメントは、内部に区切り（セル）を持たない
1 つの連続した再生単位である。

```json
{
  "video": { "codec": "av1", "mode": "transcode",
             "pixelWidth": 1440, "pixelHeight": 1080, "displayWidth": 1920, "displayHeight": 1080,
             "aspect": "16:9", "frameRate": "30000/1001",
             "cadence": "interlaced", "tff": true, "interlaceMode": "weave", "fieldLayout": "single",
             "interlacedRanges": [ { "startMs": 0, "endMs": 30030 } ] },
  "audio": [
    { "startMs": 0, "endMs": 12635, "tracks": [
        { "track": 1, "source": 1, "codec": "opus", "channels": 2, "dualMono": true, "name": "日本語\n英語", "language": "jpn" } ] },
    { "startMs": 12635, "endMs": 30030, "tracks": [
        { "track": 1, "source": 1, "codec": "opus", "channels": 2, "language": "jpn" },
        { "track": 2, "source": 2, "codec": "opus", "channels": 2, "name": "解説", "language": "jpn" } ] }
  ],
  "subtitle": [ { "source": 1, "track": 0, "type": "text" } ],
  "timing": { "totalMs": 30030 }
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `video` | オブジェクト | 必須 | 映像の属性（10 章）。 |
| `parts` | 配列 | 任意 | パーツ（10.4・10.5 節）。省略時は `av.mkv` 1 つ。 |
| `audio` | 配列 | 必須 | 音声の構成の時間変化（11 章）。音声が無ければ空の配列。 |
| `subtitle` | 配列 | 必須 | このセグメントが持つ字幕の物理トラックの一覧（13 章）。無ければ空の配列。 |
| `subtitle[].source` | 整数 | 必須 | 字幕の安定キー（12.2 節）。 |
| `subtitle[].type` | 文字列 | 必須 | `"text"` または `"image"`。 |
| `subtitle[].track` | 整数 | 任意 | 参考値。字幕は mkv に入れないので、読み手は使わない。 |
| `timing.totalMs` | 数値 | 必須 | セグメントの長さ（ミリ秒）。 |

### 9.1 メディアのファイル（`av.mkv`）

- 映像と音声を 1 つの Matroska に入れる。**字幕は入れてはならない**（字幕の実体は `subs/`。13 章）。
- タイムスタンプは**セグメント内で 0 基準**とする。先頭はデコードを始められるフレーム（キーフレーム）でなければならない。
- トラックの並びは、**映像が先、音声が後**とする。映像のトラック数は、通常 1、`fieldLayout:"dual"`（10.3 節）なら 2 である。
  音声の `track` は、この mkv の中のトラックの番号（0 始まり。映像を含めて数える）である。
- Matroska のタイムスタンプの精度は、**1 マイクロ秒**（`TimestampScale` = 1000）にすべきである
  （参考：フィールド単位の時刻を焼き込むため。1 ミリ秒では 59.94 フィールド/秒の時刻を表せない）。

## 10. 映像

### 10.1 映像の属性（`seg.json` の `video`）

| キー | 型 | 必須 | 意味 | 省略時 |
|---|---|---|---|---|
| `codec` | 文字列 | 必須 | `"h264"`・`"h265"`・`"av1"` | `"h264"` |
| `mode` | 文字列 | 任意 | `"transcode"`（再符号化した）・`"copy"`（元のビットストリームのまま） | — |
| `pixelWidth`・`pixelHeight` | 整数 | 必須 | 符号化した画素の大きさ。`interlaceMode:"fields"` では高さが元の半分（10.3 節）。 | — |
| `displayWidth`・`displayHeight` | 整数 | 必須 | 表示する大きさ（画素の縦横比を当てた後）。 | — |
| `aspect` | 文字列 | 必須 | 表示の縦横比。`"16:9"`・`"4:3"` など。 | — |
| `frameRate` | 文字列 | 必須 | 元の素材のフレームレート（有理数。`"30000/1001"`）。 | — |
| `cadence` | 文字列 | 必須 | `"progressive"`・`"interlaced"`・`"soft-telecine"`（10.2 節） | — |
| `tff` | 真偽 | 任意 | フィールドの順。`true`＝トップフィールドが先。 | `true` |
| `interlaceMode` | 文字列 | 任意 | インターレースの格納方式。`"weave"`・`"fields"`（10.3 節） | `"weave"` |
| `fieldLayout` | 文字列 | 任意 | `fields` の格納の形。`"dual"`・`"single"`（10.3 節） | `"single"` |
| `interlacedRanges` | 配列 | 任意 | 実際にインターレースな区間（10.2 節）。 | 区間なし |

- **知らない `codec`**：読み手は、そのセグメントの映像を復号しようとしてはならず、対応していないことを利用者に
  知らせるべきである（参考：別のコーデックとして復号すると、壊れた映像を出す）。
- `"av1"` の mkv では、コーデックの初期化データ（`av1C`）を CodecPrivate に入れなければならない。
- `"h264"`・`"h265"` では、**各キーフレームの前にパラメータセット**（H.264 は SPS・PPS、H.265 は VPS・SPS・PPS）を
  ストリームの中に入れなければならない（x264・x265 の `repeat-headers`）。読み手は、CodecPrivate に頼らず、どの
  キーフレームからでも復号を始められる（参考：シーク・セグメントの連結・解像度の違うパーツの連結で、復号器を
  初期化し直さずに済む）。書き手は CodecPrivate も正しく入れるべきである（汎用の再生器のため）。
- 予約：`fieldTiming`（フレームごとの表示フィールド数の明示）と `color`（色域・伝達特性・HDR の静的メタデータ）は
  将来のために予約する。書き手はこの名前を別の意味で使ってはならない。

### 10.2 ケイデンス

再生器は、元の表示のケイデンスを次のように再現する。**表示の時刻は、mkv のタイムスタンプに焼き込まれている**
（ソフトテレシネの各フレームの表示時間を含む）。メタデータは「どのフレームをデインターレースするか」を決めるために使う。

- **`"progressive"`**：そのまま表示する。
- **`"interlaced"`**：インターレースの素材（例 59.94i・50i）。`interlacedRanges` の区間のフレームを、
  再生器がデインターレース（bob など）してフィールドの頻度で表示する。
- **`"soft-telecine"`**：24p のフィルムを 3:2 などのプルダウンで載せた素材。Kuroko は **24p のフレームを保ち**、
  各フレームの表示時間（プルダウンで 2 フィールドか 3 フィールドか）を **mkv のタイムスタンプに焼き込む**。
  これで、ハードテレシネに焼き込まずに元の 24p とテレシネの表示を再現できる。
  映画の中に実際のインターレースの区間（ディゾルブなど）があれば、その区間を `interlacedRanges` に書く。

#### 途中でケイデンスが変わる映像（参考）

1 つのセグメントの中で、ケイデンスが何度変わってもよい。次の仕組みを組み合わせて、MPEG-2 のフレームごとの
フラグ（`progressive_frame`・`repeat_first_field`・`top_field_first`）で表せていた切り替わりを、コーデックによらず表す。

| MPEG-2 で表していたこと | Kuroko での表し方 |
|---|---|
| フレームごとの表示時間（3:2 プルダウンの 2 フィールド・3 フィールド、周期の崩れ） | 各フレームの mkv のタイムスタンプ |
| どのフレームがインターレースか（フィルムの中のビデオの場面・ディゾルブ） | `interlacedRanges` の区間 |
| フィールドの順（`top_field_first`） | `tff` |
| フィルムとインターレースで格納の高さを変えたいとき（`fields`） | パーツ（10.4 節） |

例えば、24p のフィルムの本編の途中に 59.94i のビデオの場面が挟まる映像では、フィルムの部分は 24p のフレームを
プルダウンどおりの表示時間で、ビデオの部分は 29.97 フレーム/秒のインターレースのフレームとして格納し、ビデオの部分の
時刻を `interlacedRanges` に書く。再生器は、フィルムの部分をそのまま、ビデオの部分をデインターレースして表示する。
符号化はプログレッシブのフレームの並びとして行うので、AV1・H.264・H.265 のどれでもよい。

`interlacedRanges` は、**実際にインターレースで、デインターレースすべきフレームの区間**の並び（セグメント内の
0 基準の時刻）である。区間に入らないフレームは、デインターレースしてはならない（プログレッシブの絵を
デインターレースすると、解像度が落ちてちらつく）。省略または空の配列は「区間なし」を表す。

### 10.3 インターレースの格納方式

- **`"weave"`**：トップとボトムのフィールドを **1 枚（全高）に織り込んで**符号化する。H.265 と AV1 はフィールドの符号化の
  道具を持たないので、織り込んだ絵をプログレッシブとして符号化する（フィールドの詰め替えは無損失）。
  H.264 はフィールド符号化（PAFF など）を使ってもよい。再生器は 1 行おきにトップとボトムへ分けてデインターレースする。
- **`"fields"`**：トップとボトムを、**それぞれ高さが半分のプログレッシブのフレーム**として符号化する。
  `pixelHeight` は元の半分になる。動きのあるインターレースで櫛状のノイズが消え、`weave` より圧縮が効く。
  再生器は、半分の高さのフレームを 1 フィールドとして全高へ戻して表示する。格納の形は `fieldLayout` で示す。
  - **`"dual"`（推奨）**：トップとボトムを **2 本の映像トラック**に分ける。**トラック 0＝トップ（偶数ライン）、
    トラック 1＝ボトム（奇数ライン）**。各トラックは元のフレームレートで、**同じ元フレームの 2 つのフィールドは
    同じタイムスタンプ**を持つ。上下はトラックの番号で決まるので、取り違えが起きない。音声はトラック 2 以降。
  - **`"single"`**：1 本のトラックにトップ・ボトム・トップ…と、半分の高さ・倍のフレームレートで交互に入れる。
    上下をタイムスタンプの位相から推し量るので、境目で取り違えうる。新しく書くときは `"dual"` を使うべきである。
- **`fields` は、実際のインターレースの区間にだけ使う。** ソフトテレシネのフレームは表示時間が一定でないので
  `fields` では表せない。ソフトテレシネのフレームは全高で格納しなければならない。
- 同じセグメントの中にフィルムと実際のインターレースが混ざるときは、**パーツ（10.4 節）**に分けて、
  インターレースのパーツを `fields`、フィルムのパーツを全高で格納してよい。混在をまるごと `weave` にしてもよい。

### 10.4 パーツ（`parts`）

1 つのセグメントの中で、フレームの高さ（解像度）や格納方式が変わるときは、セグメントを分けずに
**パーツ**に分ける（参考：1 本の符号化ストリームに 2 つの解像度は載らない。セグメントを分けないのは、
タイトルの論理構造をセグメント単位で持つため）。

```json
"parts": [
  { "file": "av.p00.mkv", "durationMs": 92500,  "pixelHeight": 480, "interlaceMode": "weave",  "fieldLayout": "single" },
  { "file": "av.p01.mkv", "durationMs": 845000, "pixelHeight": 240, "interlaceMode": "fields", "fieldLayout": "dual" }
]
```

| キー | 型 | 必須 | 意味 | 省略時 |
|---|---|---|---|---|
| `file` | 文字列 | 必須 | パーツのファイル（セグメントのディレクトリからの相対パス）。 | — |
| `durationMs` | 数値 | 必須 | パーツの長さ。セグメントの中での位置（連結のずらし量）を決める。 | — |
| `pixelHeight` | 整数 | 任意 | 参考値。符号化した高さ。 | — |
| `interlaceMode` | 文字列 | 任意 | このパーツの格納方式。 | `"weave"` |
| `fieldLayout` | 文字列 | 任意 | このパーツの格納の形。映像のトラック数（`"dual"` は 2）を決める。 | `"single"` |
| `still` | 真偽 | 任意 | 静止パーツ（10.5 節）。 | `false` |

- `parts` があるとき、`av.mkv` は使わない。読み手は各パーツを並びの順に、**それまでのパーツの `durationMs` の和**だけ
  ずらして連結し、1 つのセグメントとして再生しなければならない。
- 各パーツのタイムスタンプは、パーツの中で 0 基準である。
- トラックの構成は、パーツの中では一定で、パーツごとに違ってよい（`"dual"` のパーツは映像 2 本＋音声、
  それ以外は映像 1 本＋音声）。
- 音声は、各パーツの `durationMs` の間、**途切れずにそろっている**べきである。パーツの終わりを超えた音声は、
  読み手がパーツの境目で切り詰めなければならない。

### 10.5 静止パーツ（`still`）

**映像の長さが `durationMs` よりずっと短い**パーツには、`still: true` を書く。典型は「映像 1 枚＋音声数秒」
（静止画に音声だけが流れる区間）である。

- パーツの占める時間は常に `durationMs` で決まる。再生器は、**最後の映像フレームを `durationMs` の終わりまで表示し続け**、
  音声はパーツの長さいっぱい再生しなければならない。
- 再生器は、静止パーツの映像を投入したら、デコーダが抱えているフレームを**すぐに取り出さ**なければならない
  （参考：デコーダは並べ替えのためにフレームを抱え、次の入力が来るまで出さないことがある。付録 A.1）。
- タイトルやセグメントの終わりは、映像の終わりだけでなく、**音声の再生が終わるまで**待って判定すべきである。

## 11. 音声

### 11.1 音声の構成（`seg.json` の `audio`）

`audio` は、**時刻の区間（スパン）の並び**である。各スパンの `tracks` が、**その区間で選べる音声の全体**を表す。
放送の番組の切り替わりなどで、音声の本数・名前・デュアルモノが時間で変わることを表す。

| キー | 型 | 必須 | 意味 | 省略時 |
|---|---|---|---|---|
| `startMs`・`endMs` | 数値 | 必須 | スパンの区間（セグメント内の 0 基準）。 | — |
| `tracks` | 配列 | 必須 | この区間の音声トラック。 | — |
| `tracks[].track` | 整数 | 必須 | mkv の中のトラック番号（9.1 節）。 | — |
| `tracks[].source` | 整数 | 必須 | 論理トラックと結ぶ安定キー（12.2 節）。 | — |
| `tracks[].codec` | 文字列 | 必須 | `"opus"`・`"ac3"`・`"dts"`・`"pcm"`・`"mp2"`・`"aac"` など。 | — |
| `tracks[].channels` | 整数 | 必須 | チャンネル数。 | — |
| `tracks[].dualMono` | 真偽 | 任意 | この区間でデュアルモノ（L＝主・R＝副）か。`channels` が 2 のときだけ真にしてよい。 | `false` |
| `tracks[].name` | 文字列 | 任意 | 音声の名前。多言語の名前は改行で区切る（`"日本語\n英語"`＝主・副）。 | — |
| `tracks[].language` | 文字列 | 任意 | 言語（ISO 639-2 の 3 文字）。 | — |
| `tracks[].loudness` | オブジェクト | 任意 | ラウドネス制御（11.2 節）。 | 制御なし |

- スパンの境目は、どれかのトラックの構成（本数・名前・デュアルモノ）が変わる点である。
- ある区間で実データを持たないトラックは、その区間のスパンの `tracks` に含めない。
- **チャンネル数が途中で変わる音声**（例：冒頭がステレオで本編が 5.1ch）は、区間ごとに別の mkv トラックに置き、
  スパンで指し分けなければならない（参考：Matroska ではチャンネル数はトラックの属性で、Opus はさらに
  初期化データに入るため、1 本のトラックの途中では変えられない）。各トラックは、自分の受け持つ区間にだけデータを持つ。
- 再生器は、提示している時刻を含むスパンの `tracks` を、音声の選択肢として示すべきである。
- デュアルモノのトラックは、再生器が主（L）・副（R）・主＋副に分けて選べるようにすべきである。
  `channels` が 2 でないトラックの `dualMono` は無視しなければならない。
- 音声はフルレンジのまま格納すべきである。マルチチャンネル（5.1・7.1）を保ってよい。

### 11.2 ラウドネス制御（`loudness`）

音声の**サンプルはフルダイナミックレンジのまま格納**し、ダイナミックレンジの制御（DRC）と会話音量の正規化は
**焼き込まずにメタデータとして持ち**、再生時に任意で当てる。

```json
"loudness": { "type": "ac3", "dialogLevelDb": -27.0, "file": "loudness/1.json" }
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `type` | 文字列 | 必須 | 制御の型。`"ac3"`（11.2.1）・`"dts"`（11.2.2）。値の意味と当て方を決める。 |
| `dialogLevelDb` | 数値 | 任意 | `"ac3"` 型の会話音量（11.2.1）。 |
| `dialogGainDb` | 数値 | 任意 | `"dts"` 型の会話音量（11.2.2）。 |
| `file` | 文字列 | 任意 | ゲインの変化（エンベロープ）のファイル（セグメントのディレクトリからの相対パス）。無ければエンベロープ無し。 |

- **型は格納のコーデックとは独立**である。例えば、AC-3 から Opus へ再符号化したトラックに `"ac3"` 型の制御を持たせてよい。
- 新しい型を足すときは、値の範囲と当て方を定めて名前を付ける。既存の型の意味は変えない。

**エンベロープのファイル**（`loudness/<source>.json` に置くべきである）：

```json
{
  "type": "ac3",
  "drc":   { "mode": "ac3-line", "points": [ [0, 0.0], [5.333, -3.5], [10.667, -6.0], [16.0, 0.0] ] },
  "drcRf": { "mode": "ac3-rf",   "points": [ … ] }
}
```

- `type`：`seg.json` 側と同じ型名（ファイル単体で読めるよう、ここにも書く）。
- `points`：**変化点の並び** `[時刻ms, ゲインdB]`。各点のゲインは**次の点まで一定**（階段状）。時刻は**そのトラックの
  音声の先頭を 0** とする。続く同じ値は 1 点にまとめるべきである。0 dB だけのエンベロープは省いてよい。

#### 11.2.1 `"ac3"` 型

- **会話音量**：`dialogLevelDb`。**そのトラックの台詞のレベル**（0 dBFS からの下がり幅。負の値）を表す
  **測定値であり、当てるゲインではない**。
- **エンベロープ**：`drc`（`mode: "ac3-line"`。通常の圧縮。−24〜+24 dB）、`drcRf`（`mode: "ac3-rf"`。より強い圧縮。任意）。

#### 11.2.2 `"dts"` 型

- **会話音量**：`dialogGainDb`。**デコーダの出力にそのまま当てるゲイン**（負の値。0＝正規化しない）。
  `"ac3"` 型の `dialogLevelDb` とは意味が違う（あちらは測定値）。混同してはならない。
- **エンベロープ**：`drc`（`mode: "dts"`。埋め込みのダイナミックレンジ係数）。

#### 11.2.3 再生時の適用

- 再生器は、ラウドネス制御を**任意で**当ててよい。**既定は当てない（フルレンジ）**とすべきである。
  知らない `type` は当ててはならない。
- 当てるときは、デコード後の PCM にゲインを掛ける（`× 10^(dB/20)`）。`points` の時刻をサンプルの位置へ写し、
  区間ごとに一定のゲインを当てる。
- **ダイナミックレンジ**（両方の型）：`applied_dB = drc_dB × s`（`s` は 0〜1 の強さ）。`"ac3"` 型でより強い圧縮が
  要るときは、`drc` の代わりに `drcRf` を使う。
- **会話音量**（**型によって当て方が逆**）：

  | 型 | 当て方 |
  |---|---|
  | `"ac3"` | 目標の台詞レベル `targetDb` を決め、`applied_dB = targetDb − dialogLevelDb`。例：`dialogLevelDb = −27` を `targetDb = −31` にそろえるなら −4 dB。**`dialogLevelDb` の値そのものを当ててはならない。** |
  | `"dts"` | `applied_dB = dialogGainDb`。そのまま当てる。 |

## 12. VIDEO/Tnn/title.json

タイトルは**論理だけ**（プレイリスト・論理トラック・章・番組）を持ち、メディアの実体は `SEGMENTS/` を指す。
**メディアの属性（コーデック・チャンネル数・デュアルモノ・解像度・ケイデンス）を持ってはならない**（すべて `seg.json`）。

```json
{
  "id": 1, "name": "本編",
  "timing": { "totalMs": 1800000 },
  "audio": [ { "number": 1, "language": "jpn", "source": 1 } ],
  "subtitle": [ { "number": 1, "type": "text",  "language": "jpn", "name": "字幕", "source": 1 },
                { "number": 2, "type": "image", "language": "jpn", "name": "字幕（画像）", "source": 2 } ],
  "chapters": [ { "number": 1, "startMs": 0, "name": "オープニング" } ],
  "events": [ { "startMs": 0, "endMs": 1800000, "name": "番組名", "eventId": 1024,
                "startTime": "2026-01-01T19:00:00+09:00", "desc": "…" } ],
  "playlist": [ { "seg": "S0001", "startMs": 0 } ]
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `id` | 整数 | 必須 | タイトル番号（`disc.json` の `titles[].id`）。 |
| `name` | 文字列 | 任意 | タイトルの名前。 |
| `timing.totalMs` | 数値 | 必須 | タイトルの長さ。 |
| `audio` | 配列 | 必須 | 論理音声（12.2 節）。`number`（1 始まり）・`language`（任意）・`source`。 |
| `subtitle` | 配列 | 必須 | 論理字幕。`number`（1 始まり）・`type`（`"text"`／`"image"`）・`language`・`name`（任意）・`source`。 |
| `chapters` | 配列 | 任意 | 章。`number`・`startMs`（タイトル内の時刻）・`name`（任意）。 |
| `events` | 配列 | 任意 | 時刻付きの番組情報（12.3 節）。 |
| `playlist` | 配列 | 必須＊ | セグメントの並び（12.1 節）。＊アングルを持つタイトルは `angles`（12.4 節）。 |
| `angleType`・`angles` | | 任意 | アングル（12.4 節）。 |

### 12.1 プレイリスト

- `playlist[].seg`：セグメントの識別子（`SEGMENTS/<seg>/`）。
- `playlist[].startMs`：タイトルの時間軸での、そのセグメントの開始時刻。
- 再生器は、各セグメントの映像・音声・字幕の時刻に `startMs` を足して、タイトルの時間軸へ並べなければならない。
- 複数のタイトルが同じセグメントを指してよい（共有）。

### 12.2 論理トラックと物理トラック（`source`）

`source` は、論理トラックと物理トラックを結ぶ**安定キー**である。

1. 論理音声 `audio[number = N].source` を得る。
2. 再生中のセグメントの、提示時刻を含むスパンの `tracks` から、同じ `source` のトラックを選ぶ。
3. その `track` が mkv の中のトラックである。

- 書き手は、**同じ内容のトラックには、すべてのセグメントで同じ `source`** を使わなければならない。
  これで、セグメントの境目や番組の切り替わりで構成が変わっても、タイトルを作り直さずに済む。
- 字幕も同じ（`subtitle[].source` → `seg.json` の `subtitle[]` → `subs/` の実体。13 章）。
- 参考：放送の TS から作るなら元のストリーム（PID 相当）、DVD から作るなら物理サブストリームの番号が、`source` に向く。

### 12.3 番組情報（`events`）

再生位置によって**表示名が変わる**内容（放送の録画の番組の切り替わりなど）を表す。

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `startMs`・`endMs` | 数値 | 必須 | 区間（タイトル内の時刻）。 |
| `name` | 文字列 | 任意 | 番組名。 |
| `eventId` | 整数 | 任意 | 番組の識別子。 |
| `startTime` | 文字列 | 任意 | 放送の開始時刻（ISO 8601）。 |
| `desc` | 文字列 | 任意 | 内容の説明。 |

- 再生器は、表示名を「提示時刻を含む `events` の `name` → 無ければタイトルの `name`」の順で決めるべきである。

### 12.4 アングル（`angleType: "bd"`）

同じ内容の**別の版**を、1 つのタイトルの中に並べる。**アングルごとに違うのはプレイリストだけ**で、
長さ・章・音声・字幕はタイトルで共通である。

```json
{
  "id": 2, "name": "本編",
  "angleType": "bd",
  "angles": [
    { "number": 1, "playlist": [ { "seg": "S0001", "startMs": 0 }, { "seg": "S0005", "startMs": 120245 } ] },
    { "number": 2, "playlist": [ { "seg": "S0003", "startMs": 0 }, { "seg": "S0005", "startMs": 120245 } ] }
  ],
  "timing": { "totalMs": 8170695 },
  "audio": [ … ], "subtitle": [ … ], "chapters": [ … ]
}
```

- **`angles` と `playlist` は排他**である。`angles` を持つタイトルは `playlist` を持ってはならない。
- `angles[].number`：1 始まりの通し番号。`angles[].name`：任意の名前。
- `angleType`：`"bd"`（この節。タイトル全体が別のプレイリスト）、`"dvd"`（第II部の 18 章）。
  **知らない値なら、再生器はアングル 1 だけを再生**しなければならない。
- 書き手は、**すべてのアングルで長さ・章・音声・字幕が同じ**であることを確かめてからアングルにまとめなければならない。
  成り立たないときは、別々のタイトルとして書く。
- 再生器の動き（参考）：同じタイトルの別アングルへ切り替えるときは、位置・音声・字幕を保ったまま切り替える。
  レジュームは（タイトル・アングル・位置・音声・字幕）を保つ。

## 13. 字幕

字幕は **`SEGMENTS/S####/subs/` に物理的に置き**、`title.json` の `subtitle[].source` から参照する
（`subtitle[number].source` → `seg.json` の `subtitle[]` → `subs/<種類>/<source>`）。mkv には入れない。
字幕の種類は、**テキスト型**（13.1・13.2）と**画像型**（13.3）である。

### 13.1 テキスト型（`subs/text/<source>.json`）

時刻の付いたテキスト。行と、同じ書式の文字の並びで書く。

```json
{ "type": "text", "lang": "jpn", "name": "字幕",
  "charset": "unicode",
  "canvas": { "width": 960, "height": 540 },
  "cues": [ { "startMs": 38810, "endMs": 41710,
              "lines": [
                { "x": 438, "y": 413,
                  "runs": [ { "text": "東京", "w": 36, "h": 36, "hs": 4, "vs": 24, "color": "#00FF00" },
                            { "text": "目黒区の自由が丘｡", "w": 36, "h": 36, "hs": 4, "vs": 24, "color": "#00FF00", "size": "medium" } ] },
                { "x": 558, "y": 395,
                  "runs": [ { "text": "めぐろ", "w": 18, "h": 18, "hs": 2, "vs": 6, "color": "#00FF00", "size": "small" } ] } ] } ] }
```

| キー | 型 | 必須 | 意味 | 省略時 |
|---|---|---|---|---|
| `type` | 文字列 | 必須 | `"text"`。 | — |
| `lang` | 文字列 | 任意 | 言語。 | — |
| `name` | 文字列 | 任意 | 名前。 | — |
| `charset` | 文字列 | 任意 | 文字と描き方の決まり（13.2 節）。 | `"unicode"` |
| `canvas` | オブジェクト | 必須 | 位置の座標系（`width`・`height`）。再生器は、canvas 全体を映像の表示範囲へ拡大縮小して重ねる。 | — |
| `drcs` | 配列 | 任意 | 外字の形（13.2 節）。 | — |
| `cues` | 配列 | 必須 | 表示の単位。 | — |

**cue**：

- `startMs`・`endMs`：表示の区間（セグメント内の 0 基準）。**有限でなければならない**（終わりの無い表示は、
  取り込むときに次の表示や消去の時刻を `endMs` に入れて有限にする）。
- `writing`：`"horizontal"`（既定）・`"vertical"`（縦書き）。
- `lines`：行の並び。

**行（`lines[]`）**：

- `x`・`y`：その行の**先頭の文字の枠（セル）の左上**（canvas の座標）。文字は左から右へ並ぶ（縦書きは上から下）。
- `runs`：同じ書式が続く文字の並び。

**文字の並び（`runs[]`）**：

| キー | 意味 |
|---|---|
| `text` | 文字列（Unicode）。 |
| `w`・`h` | 文字の大きさ（基準の字の幅・高さ。`size` で縮む前の値）。 |
| `hs`・`vs` | 字間・行間。1 文字の枠は 幅 `w+hs` × 高さ `h+vs`（`size` に応じて縮む・伸びる）。 |
| `size` | `"normal"`（既定）・`"medium"`（横 1/2）・`"small"`（縦横 1/2。ルビなど）・`"tall"`（縦 2 倍）・`"wide"`（横 2 倍）・`"double"`（縦横 2 倍）。 |
| `color` | 文字の色。 |
| `bg` | 文字の背景色（枠を塗る）。 |
| `edge` | 縁取りの色（無ければ縁なし）。 |
| `deco` | `"underline"`・`"bold"`・`"italic"` の並び。 |
| `box` | 囲み。`"t"`・`"b"`・`"l"`・`"r"` の組み合わせ（`"tblr"`＝四方）。 |
| `flash` | `"normal"`・`"inverted"`（点滅）。再生器は描かなくてよい。 |

- 色は `#RRGGBB`、または透明度を含む `#RRGGBBAA`。
- **省略した項目は、同じ行の直前の run の値を引き継ぐ。** 行の最初の run は `w`・`h`・`hs`・`vs`・`color` を
  書かなければならない。ほかの既定は、`size` が normal、背景・縁・装飾・囲み・点滅なし。
  途中で「なし」へ戻すときは明示する：`bg:"#00000000"`・`edge:"none"`・`deco:[]`・`box:""`・`flash:"none"`・`size:"normal"`。

### 13.2 文字と描き方の決まり（`charset`）

- **`"unicode"`**（既定）：普通の Unicode のテキスト。フォントは再生器が選ぶ。
- **`"arib"`**：**日本の地上・BS デジタル放送の字幕（ARIB STD-B24）**に由来することを示す。
  - 文字は Unicode で持つ。ARIB の追加記号・追加漢字は、その Unicode の対応字で書く。
  - **DRCS**（番組ごとに字幕のデータで形を送ってくる外字）は、`text` の中では**補助私用面の文字（U+F0000 から順）**で表し、
    その形を `drcs[]` に持つ。同じ放送のコードでも形が違えば、別の文字にする（`drcs[]` は形ごとに 1 件）。
  - 中サイズ（`size:"medium"`）の英数字・記号は、表示どおり半角の Unicode で書く。
  - 再生器は、ARIB の外字を含むフォントで描き、DRCS は `drcs[]` の形で描くべきである。
  - 表示 1 回が字幕のデータ 1 つに当たり、**次の字幕のデータ（消去だけのものを含む）で置き換わる**。
    取り込むときは、この決まりで `endMs` を決める。
- **`drcs[]`**：`char`（`text` で使う私用面の文字。`"U+F0000"` の形）、`width`・`height`（ドット）、
  `depth`（1 画素のビット数。1＝2 階調・2＝4 階調）、`pattern`（ARIB の DRCS のパターンデータそのまま。左上から
  行の順に詰めたビット列を base64 で）。

### 13.3 画像型（`subs/img/<source>/index.json`）

画像の字幕。cue ごとに次の 3 つの表し方があり、**再生器は `pgs` → `spu` → `steps` の順に優先**する
（解釈できない表し方は飛ばす）。書き手は、少なくとも 1 つを書かなければならない。

```json
{ "type": "image", "lang": "jpn", "canvas": { "width": 720, "height": 480 },
  "cues": [ { "startMs": 12345, "endMs": 15000, "spu": "0001.spu" },
            { "startMs": 16000, "endMs": 18000,
              "steps": [ { "atMs": 0, "x": 100, "y": 420, "image": "0002.png", "opacity": 1.0 } ] } ] }
```

- **`spu`**：同じディレクトリの DVD-Video のサブピクチャの生データ（1 回の表示ぶん）。表示中の変化
  （フェード・行の範囲ごとの色の出し分け）がすべて中に入っている。色は、タイトルの `palette`（第II部 17 章）で描く。
- **`pgs`**：同じディレクトリの Blu-ray の Presentation Graphic Stream の生データ。**表示を始める Display Set から、
  消去の直前まで**を 1 ファイルに入れる。パレットはストリームの中にある。
  - 既知の制限（参考）：Display Set ごとの表示時刻は持たない。1 つの cue に複数の Display Set があるとき
    （パレットの更新によるフェードなど）は、再生器は順に復号して最後の状態を cue の全体に出してよい。
- **`steps`**：汎用の画像（PNG）と不透明度。`atMs`（cue の始まりからの時刻）・`x`・`y`（canvas の座標）・
  `image`（同じディレクトリの PNG）・`opacity`（0〜1）。色数などの制約は無い。
- `canvas`：座標系の大きさ（映像の表示の大きさ）。

## 14. `none` で表せないもの（参考）

- 動的な HDR のメタデータ（Dolby Vision RPU・HDR10+）。
- 高度なテキスト字幕（ASS/SSA のアニメーション・カラオケ・埋め込みフォント）。
- 複数の映像を同時に出すもの（ピクチャー・イン・ピクチャー）、データ放送、時刻付きのデータ（GPS など）。

# 第II部　コントローラ `dvd-video-vm`

コントローラは、`none` の器の上にナビゲーションの層を足すものである。`dvd-video-vm` は、**DVD-Video 互換の
仮想マシン（VM）**でメニュー・分岐・操作の制限を表す。セグメント（物理）・`seg.json`・字幕は `none` をそのまま使い、
その上にメニュー・VM の命令・論理と物理の対応を足す。

- **VM の命令の意味は、本書では定めない。** 各命令は DVD-Video のナビゲーションの 8 バイトの命令であり（21 章）、
  その意味は DVD-Video の仮想マシンに従う。本書は、命令を Kuroko の器へどう収めるかだけを定める。
  （参考：命令の意味は、公開されている解析資料やオープンソースの DVD ナビゲーションの実装から知ることができる。）
- DVD-Video の用語（VMG・VTS・PGC・セル・PCI など）は、DVD-Video での意味で使う。

## 15. 概要

### 15.1 DVD-Video との対応（参考）

| DVD-Video | Kuroko | 備考 |
|---|---|---|
| ディスク（VMG） | `CONTROL/disc.json` | リージョン・FirstPlay・メニューの一覧・VM の命令 |
| タイトル | `VIDEO/Tnn/title.json` | VM の JumpTT などが通し番号で引く |
| PGC のセルの並び／VOB | `SEGMENTS/`（共有の単位で重複を除く。19 章） | |
| 音声（論理と物理の対応表） | `title.json`（論理→物理）＋`seg.json`（物理→トラック） | |
| サブピクチャ（表示モード別） | 画像型の字幕（13.3 節）＋`title.json` の表示モード別の対応 | 4:3・ワイド・レターボックス・パン&スキャン |
| メニュー（PGC・ボタン） | `MENU/<domain>/PGC<nn>/`（20 章） | 時刻付きのボタン情報 |
| VM の命令（PRE・POST・CELL・FirstPlay） | JSON に埋め込む（21 章） | 別のバイナリは持たない |
| 操作の制限／セルの静止／セルの命令 | `uopControl`／`still`／`commandNr`・`cellCommand` | |
| 静止画のセル（映像 1 枚＋音声数秒） | 静止パーツ（10.5 節） | セルの長さを `durationMs` に写す |
| 16 色のパレット | `palette` | ボタンと字幕の描画 |

### 15.2 VM を実行する再生・しない再生

再生器は、次のどちらかで再生してよい。

- **VM を実行する再生**：FirstPlay・メニュー・PGC の PRE と POST・セルの命令・セルの静止・レジューム（RSM）を、
  すべて DVD-Video のとおりに実行する。
- **VM を実行しない再生**（メディアプレーヤーとしての再生）：タイトルを直接選んで再生する。**VM の命令を一切
  実行しない**（タイトルの終わりの POST、セルの命令、セルの静止を含む）。操作の制限（UOP）も適用しない。
  タイトルの終わりでは次のタイトルへ進んでよい。再生を始める状態は、`firstPlayback`（8.1 節）に従う。

`controller: "none"` のファイルは、常に「VM を実行しない再生」になる。

## 16. CONTROL/disc.json の拡張

```json
{
  "region": 0,
  "firstPlay": { "domain": "vmg", "pgc": 0 },
  "firstPlayCommands": [ { "hex": "3006000000420000", "asm": "JumpSS VMGM menu=Title" } ],
  "firstPlayback": { "title": 1, "audio": 1, "subtitle": 0 },
  "titles": [ { "id": 1, "vts": 1, "vtsTitle": 1, "menuDomain": "VTS01", "durationMs": 4659633.9, "video": "VIDEO/T01" } ],
  "menuDomains": [
    { "id": "VMGM", "pgcs": [ { "pgc": 1, "type": "Title", "path": "MENU/VMGM/PGC01",
                                "commands": { "pre": [ … ], "post": [ … ], "cell": [ … ] }, "uopControl": 0 } ] }
  ],
  "titleDomains": [
    { "vts": 6, "pgcs": [ { "pgc": 1, "title": 7 },
                          { "pgc": 2, "title": 0, "commands": { "pre": [ … ], "post": [ … ], "cell": [ … ] } } ] }
  ]
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `region` | 整数 | 任意 | リージョンのマスク（DVD-Video の値）。 |
| `firstPlay` | オブジェクト | 任意 | 起動時に実行する PGC。`domain`（`"vmg"` またはメニューのドメイン）・`pgc`（番号。0＝FirstPlay の PGC）。 |
| `firstPlayCommands` | 配列 | 任意 | FirstPlay の PGC の命令（21 章）。 |
| `firstPlayback` | オブジェクト | 任意 | VM を実行しない再生の開始状態（8.1 節）。**`firstPlay` とは別物**。 |
| `titles[]` | 配列 | 必須 | `none` の項目（8 章）に加えて、`vts`（VTS 番号）・`vtsTitle`（VTS 内のタイトル番号）・`menuDomain`（関係する VTS メニューのドメイン）。 |
| `menuDomains[]` | 配列 | 任意 | メニューのドメイン。`id`（`"VMGM"`・`"VTS01"`…）・`pgcs[]`。 |
| `menuDomains[].pgcs[]` | | | `pgc`（番号）・`type`（`"Title"`・`"Root"`・`"Subpicture"`・`"Audio"`・`"Angle"`・`"Chapter"`、または無し）・`path`（メニューのディレクトリ。20 章）・`commands`（PRE・POST・CELL の命令）・`uopControl`（禁止する操作の 32 ビット。0＝すべて許可）。 |
| `titleDomains[]` | 配列 | 任意 | タイトルのドメイン（VTS の PGC の表。16.1 節）。 |

- `firstPlayback` の `audio`・`subtitle` は、`none` と同じく `title.json` の `number` で書く。

### 16.1 タイトルのドメイン（`titleDomains`）

VM の Link 系の命令（LinkPGCN・次・前・上の PGC）は、**今いるドメインの中の** PGC を指す。タイトルの再生中は、
その VTS のタイトルのドメインで解決しなければならない。VTS の PGC の表には、**タイトル番号を持たない中間の PGC**
（PRE で別の所へ移すだけのものなど）があり得るので、PGC 番号ごとに次を持つ。

- `pgc`：VTS の中の PGC 番号（1 始まり）。
- `title`：対応するタイトル番号（`titles[].id`）。**0＝タイトル番号を持たない中間の PGC**。
- `commands`：中間の PGC の命令（PRE・POST・CELL）。タイトルの PGC の命令は `title.json` の `pgcCommands` にあるので持たない。

## 17. VIDEO/Tnn/title.json（`dvd-video-vm`）

`dvd-video-vm` の `title.json` も**論理だけ**を持つ。メディアの属性は `seg.json` にある。

```json
{
  "audio": [ { "number": 1, "source": 128, "language": "eng", "astCtl": 0 } ],
  "subtitle": [ { "number": 1, "source": 32, "spstCtl": 0, "language": "jpn",
                  "modes": { "normal": 32, "wide": 33, "letterbox": -1, "panScan": -1 } } ],
  "chapters": [ { "number": 1, "startCell": 0, "startMs": 0 } ],
  "playlist": [ { "seg": "S0001", "titleCellStart": 0, "cellCount": 1, "startMs": 0 } ],
  "programs": [ { "pgn": 1, "entryCell": 0 } ],
  "cells": [ { "index": 0, "startMs": 0, "still": 0, "commandNr": 0, "seg": "S0001", "segCell": 0, "angle": 0 } ],
  "palette": [ "108080", "EB8080", … ],
  "uopControl": 0,
  "pgcCommands": { "pre": [ … ], "post": [ … ], "cell": [ … ] },
  "timing": { "totalMs": 9647567.2, "frameRate": "30000/1001", "cellBaseFrame": [ … ], "chapterFrame": [ … ] }
}
```

| キー | 意味 |
|---|---|
| `audio[]` | 論理音声（17.1 節）。 |
| `subtitle[]` | 論理字幕（17.2 節）。 |
| `chapters[]` | 章。`number`（1 始まり）・`startCell`（開始セルの 0 始まりの番号）・`startMs`。 |
| `playlist[]` | セグメントの並び（17.3 節）。アングルを持つタイトルは `angles`（18 章）。 |
| `programs[]` | プログラム。`pgn`（1 始まり）・`entryCell`（開始セルの位置。**0 始まり**）。 |
| `cells[]` | セル（17.3 節）。 |
| `palette` | サブピクチャの 16 色のパレット。各要素は 24 ビットの値を 6 桁の 16 進で（DVD-Video と同じ Y・Cr・Cb の並び）。 |
| `uopControl` | タイトルの PGC の禁止する操作（32 ビット。0＝すべて許可）。 |
| `pgcCommands` | タイトルの PGC の命令（`pre`・`post`・`cell`。21 章）。 |
| `timing.totalMs` | タイトルの長さ。 |
| `timing.frameRate`・`cellBaseFrame`・`chapterFrame` | 参考値。セル・章の先頭の、表示順のフレーム番号（`cellBaseFrame` はセル数＋1 個で、最後は総フレーム数）。 |

### 17.1 論理音声

- `number`：論理音声の番号（1 始まり）。**DVD の論理音声番号（VM の命令 SetSTN や SPRM が参照する 0 始まりの番号）は `number − 1`** である。
- `source`：その論理音声が指す**物理サブストリームの番号**。`seg.json` の `tracks[].source` と結ぶ（12.2 節）。
  参考：AC-3 は `0x80+n`、DTS は `0x88+n`、LPCM は `0xA0+n`、MPEG 音声は `0x1C0+n`。
- `astCtl`：PGC の音声ストリームの制御で指す実際のストリーム番号（取れなければ −1）。
- 論理と物理の対応はタイトル（PGC）ごとに違ってよい（同じ物理音声を、複数の論理音声が指してもよい）。
  そのため、対応はタイトルの側に持つ。

### 17.2 論理字幕（表示モード別）

- `number`：論理字幕の番号（1 始まり）。DVD の論理サブピクチャの番号は `number − 1`。
- `source`：代表の物理サブストリームの番号（`0x20+n`）。
- `spstCtl`：PGC のサブピクチャの制御で指す実際のストリーム番号（取れなければ −1）。
- `modes`：**表示モード別の物理サブストリームの番号**（`normal`＝4:3・`wide`＝16:9・`letterbox`・`panScan`。
  無いものは −1）。再生器は、今の表示モードで物理の番号を選び、`seg.json` の `subtitle[]`（`source` が一致するもの）→
  `subs/img/<source>/` を描く。

### 17.3 セルとプレイリスト

- `cells[]` は、**PGC のセルと 1 対 1**である（VM・章・プログラムがセルの番号で参照するため）。
  - `index`：セルの番号（0 始まり）。
  - `startMs`：タイトルの時間軸での開始時刻。
  - `still`：セルの静止時間（秒）。0＝なし、−1＝無限（利用者の入力を待つ）。
  - `commandNr`：セルの終わりで実行するセルの命令の番号（`pgcCommands.cell` への **1 始まり**の索引。0＝なし）。
  - `seg`・`segCell`：このセルの実体があるセグメントと、その中でのセルの順番（0 始まり）。
  - `angle`：アングルブロックの中での順番（18 章。0＝ブロックの外）。
- **セルの長さ**は、次のセルの `startMs`（最後のセルならタイトルの長さ）との差で決まる。ただし、同じアングルブロックの
  別のアングルのセルは飛ばして数える（18 章）。
- `playlist[]`：`seg`（セグメント）・`titleCellStart`（そのセグメントが受け持つ最初のセルの番号）・`cellCount`（セルの数）・
  `startMs`（タイトルの時間軸でのセグメントの開始時刻）。セグメントは、タイトルのセル `[titleCellStart, titleCellStart+cellCount)` に当たる。
- セルのセグメントの中での位置は、「セルの `startMs` − そのセグメントの `playlist[].startMs`」で求める。

### 17.4 静止画のセル（参考）

DVD-Video には「映像 1〜数枚＋音声数秒」の静止画のセルが続くタイトルがある（警告画面の連続など）。セルの長さは IFO が
持ち、映像のストリームからは分からない。書き手は、このようなセルを**静止パーツ**（10.5 節）にし、IFO のセルの長さを
`durationMs` に入れる（付録 B.1）。

## 18. アングル（`angleType: "dvd"`）

DVD-Video のマルチアングルは**セルの単位**で、同じ区間を別のアングルで撮ったセルが、PGC のセルの並びの中に
**アングルブロック**として続く。BD のように「タイトル全体が別のプレイリスト」ではない。

```json
{
  "angleType": "dvd",
  "angles": [
    { "number": 1, "playlist": [ { "seg": "S0001", "titleCellStart": 0, "cellCount": 1, "startMs": 0 },
                                 { "seg": "S0004", "titleCellStart": 6, "cellCount": 60, "startMs": 38200 } ] },
    { "number": 2, "playlist": [ { "seg": "S0005", "titleCellStart": 1, "cellCount": 1, "startMs": 0 },
                                 { "seg": "S0004", "titleCellStart": 6, "cellCount": 60, "startMs": 38200 } ] }
  ],
  "cells": [ { "index": 0, "startMs": 0, "angle": 1, "seg": "S0001", "segCell": 0 },
             { "index": 1, "startMs": 0, "angle": 2, "seg": "S0005", "segCell": 0 },
             { "index": 6, "startMs": 38200, "angle": 0, "seg": "S0004", "segCell": 0 } ]
}
```

- **`cells[]` は、全アングルのセルを載せたまま PGC と 1 対 1** にする（アングルで間引くと、LinkCN・章・プログラムの
  参照する番号がずれる）。
- `cells[].angle`：アングルブロックの中での順番＝アングル番号（1 始まり）。0＝ブロックの外（全アングルで再生する）。
- **同じブロックのセルは `startMs` を共有する**（各アングルの長さは等しいので、時間軸はアングルによらない）。
- **アングルごとに違うのは `playlist` だけ**。ブロックの外のセグメントは、全アングルの `playlist` に同じ識別子で現れる
  （実体は 1 回だけ格納する）。
- アングルブロックのセルは、1 セル＝1 セグメントにしなければならない（あるアングルが再生するセルは番号が飛び飛びに
  なり、連続した範囲で表せないため）。
- `timing`・`chapters`・`programs`・`audio`・`subtitle`・`pgcCommands` は、アングルによらず共通である。
- 再生器は、VM のアングル番号（SPRM 3）と今のアングルを一致させなければならない。切り替えの動きは 12.4 節と同じ。

## 19. セグメントの共有

複数のタイトルが本編を共有し、導入部だけが違う（シームレスな分岐）といった構成を、**共有される範囲ごとのセグメント**に
分けて、実体を 1 回だけ格納してよい。

- 書き手は、元の物理的な位置が同じ範囲を同じセグメントにまとめてよい。
- 再生器は、プレイリストのセグメントを継ぎ目なく連結しなければならない。映像は各セグメントの先頭のキーフレームから
  続けて提示し、音声は**符号化の遅延（Opus の pre-skip など）を考慮して、サンプルの精度で**つなぐ。
- 提示の時刻は、`セグメント内の時刻 ＋ タイトルの playlist[].startMs`。**負のタイムスタンプを「時刻なし」とみなしてはならない**
  （参考：Opus の pre-skip により、セグメントの先頭の音声パケットは −6.5 ms のような実在の時刻を持つ）。

## 20. メニュー（`MENU/<domain>/PGC<nn>/`）

メニューは、PGC を**セルの単位のファイル**に分けて持つ。

```
MENU/<domain>/PGC<nn>/
├─ menu.json   メニューの情報とセルの並び
├─ C00.mkv …   セルごとの映像＋音声
└─ C00.spu …   セルごとのボタンの図柄（サブピクチャの生データ。任意）
```

### 20.1 menu.json

| キー | 型 | 意味 |
|---|---|---|
| `version` | 整数 | レイアウトと同じ値（`5`）。 |
| `domain` | 文字列 | `"VMGM"`・`"VTS01"` など。 |
| `pgc` | 整数 | PGC 番号。 |
| `menuType` | 文字列 | メニューの種類。`"Title"`・`"Root"`・`"Subpicture"`・`"Audio"`・`"Angle"`・`"Chapter"`（`disc.json` の `menuDomains[].pgcs[].type` と同じ）。該当しなければ空文字列。 |
| `uopControl` | 整数 | 禁止する操作（32 ビット）。 |
| `nextPgc`・`prevPgc`・`goUpPgc` | 整数 | 次・前・上の PGC の番号（0＝なし）。 |
| `palette` | 文字列の配列 | 16 色のパレット（各要素は 24 ビットの Y・Cr・Cb の値を 6 桁の 16 進で。`title.json` と同じ）。 |
| `video` | オブジェクト | `codec`（`"h264"`・`"h265"`・`"av1"`）・`width`・`height`・`aspect`・`interlaced`・`tff`。 |
| `audio[]` | 配列 | 音声ストリームの制御（論理音声の順に）。`available`・`number`（その論理音声が指すストリームの番号。DVD-Video の値）・`codec`（`"opus"`・`"ac3"` など）。 |
| `spstCtl[]` | 配列 | サブピクチャの制御（論理番号の順）。`available`・`n43`・`wide`・`lb`・`ps`（表示モード別の物理番号）。 |
| `commands` | オブジェクト | PGC の命令（`pre`・`post`・`cell`）。 |
| `programMap` | 整数の配列 | プログラムごとの開始セルの位置（0 始まり）。 |
| `cells[]` | 配列 | セル（20.2 節）。 |

### 20.2 セル（`cells[]`）

| キー | 意味 |
|---|---|
| `index` | セルの番号（0 始まり）。 |
| `still` | 静止時間（秒）。0＝なし、1〜254＝有限、−1＝無限。 |
| `cellCommand` | セルの終わりで実行するセルの命令の番号（1 始まり。0＝なし）。 |
| `durationMs` | このセルの mkv の長さ。 |
| `seamlessNext` | 次のセルと継ぎ目なく続くか。 |
| `static` | 実際のフレームが 1 枚だけの静止のセルか。真なら、再生器はデインターレースせず全解像度で表示すべきである。 |
| `cadence` | ケイデンス（`"interlaced"`・`"film"`・`"progressive"`・`"mixed"`）。人が読むための記録。 |
| `interlacedRanges` | デインターレースすべき区間（**このセルの中の時刻**）。空の配列＝なし。 |
| `av` | このセルの映像＋音声のファイル（`"C01.mkv"`）。 |
| `spu` | このセルのボタンの図柄のファイル（`"C01.spu"`。無ければ空文字列）。 |
| `pci[]` | 時刻付きのボタン情報（20.3 節）。 |

- 再生器は、再生するセルの `av` を順に連結して再生する。各セルの時刻は、それまでのセルの `durationMs` の和だけずらす。
- 停止とループは、セルの `still`（≠0）と `cellCommand`（≠0）で表す。
- `interlacedRanges` を持たない `menu.json` に出会ったときは、`video.interlaced` で判断してよい（参考：古い書き手）。

### 20.3 ボタン情報（`pci[]`）

各要素は、DVD-Video の PCI（1 VOBU の区間）のハイライトの情報で、`fromMs`〜`toMs`（セルの中の時刻）の間だけ有効である。
静止のセルは 1 要素である。

| キー | 意味 |
|---|---|
| `fromMs`・`toMs` | 有効な区間。 |
| `highlightStatus` | ハイライトの状態（0＝ハイライトなし）。 |
| `vobuUop` | この区間の禁止する操作（再生器は PGC の `uopControl` と論理和で判定する）。 |
| `forcedSelect`・`forcedActivate` | 強制的に選ぶ・実行するボタンの番号（0＝なし）。 |
| `buttons[]` | `number`（1 始まり）・`x0`・`y0`・`x1`・`y1`（矩形）・`colorGroup`（0〜2）・`autoAction`（0 以外なら選んだら即実行）・`up`・`down`・`left`・`right`（移動先のボタン番号）・`command`（ボタンの命令。21 章）。 |
| `colorGroups[]` | 色の組（最大 3 組）。`selectColor`・`selectContrast`・`actionColor`・`actionContrast`（各 4 要素。色はパレットの索引、コントラストは不透明度）。 |

## 21. VM の命令の JSON 表現

VM の命令は、**別のバイナリを持たず JSON に埋め込む**。命令の並びが現れる場所は、`disc.json` の `firstPlayCommands`・
`menuDomains[].pgcs[].commands`・`titleDomains[].pgcs[].commands`、`title.json` の `pgcCommands`、`menu.json` の
`commands` と `cells[].pci[].buttons[].command` である。各命令は次の形をとる。

```json
{ "hex": "3006000000420000", "asm": "JumpSS VMGM menu=Title" }
```

- `hex`：**実行する** 8 バイトの命令（16 桁の 16 進）。
- `asm`：人が読むための注釈。読み手は実行に使ってはならない。
- 読み手は、文字列だけの形（`"3006000000420000"`）も `hex` として受け付けるべきである（参考：古い書き手）。
- 別のコントローラを作るときは、そのコントローラのナビゲーションを、同じように JSON で持てばよい。

# 第III部　コントローラ `kuroko-tiny`

`kuroko-tiny` は、**メニュー・ボタン・動作を JSON で宣言的に書く**コントローラである。オーサリングツールで作る
「メニュー付き・字幕付きの多タイトル」を表すためのもので、命令の列（仮想マシン）も状態の変数も持たない。
DVD の制約（ボタンの図柄は 4 色・解像度は SD など）を受けず、高解像度の画像・透明度・動画の背景を使える。

## 22. 概要

### 22.1 レイアウト

タイトルの器は `none` と同じである（`CONTROL/disc.json`・`VIDEO/Tnn/title.json`・`SEGMENTS/`・字幕。第I部）。
`kuroko-tiny` が足すのは、ナビゲーションの `CONTROL/nav.json` と、メニューごとのフォルダ `MENU/<menuId>/` だけである。

```
example.krk
├─ KUROKO.MANIFEST              controller: "kuroko-tiny"
├─ CONTROL/disc.json            タイトルの一覧（第I部と同じ）
├─ CONTROL/nav.json             ナビゲーション（23 章）
├─ MENU/<menuId>/menu.json      メニュー 1 つ（24 章）
├─ MENU/<menuId>/…              背景の画像・動画、BGM、ボタンの画像
├─ VIDEO/Tnn/title.json         タイトル（第I部と同じ）
└─ SEGMENTS/S####/              セグメント（第I部と同じ）
```

### 22.2 コントローラに従う再生・従わない再生

- **コントローラに従う再生**では、読み手は `nav.json` の `firstPlay` から始め、メニューとボタンの動作に従う（26 章）。
- **メディアプレーヤーとしての再生**では、読み手は `nav.json` と `MENU/` を使わず、`none` と同じに再生してよい
  （タイトルを直接選んで再生する）。
- どちらで再生するかは読み手が決める（利用者の設定など）。

## 23. CONTROL/nav.json

```json
{
  "firstPlay": { "showMenu": "main" },
  "menus": [ "main", "chapters" ],
  "keys": { "menu": "main", "titleMenu": "chapters" },
  "titles": [
    { "title": 1, "onEnd": { "showMenu": "chapters" } },
    { "title": 2, "onEnd": { "playTitle": { "title": 3 } } }
  ]
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `firstPlay` | 動作 | 任意 | ファイルを開いたときの動作（25 章）。無ければ、先頭のタイトルを再生する。 |
| `menus` | 文字列の配列 | 必須 | メニューの識別子の一覧。各識別子について `MENU/<menuId>/menu.json` がなければならない。 |
| `keys.menu` | 文字列 | 任意 | 再生器の「メニュー」の操作で出すメニュー。無ければ `keys.titleMenu`。 |
| `keys.titleMenu` | 文字列 | 任意 | 再生器の「タイトルメニュー」の操作で出すメニュー。無ければ `keys.menu`。 |
| `titles[].title` | 整数 | 必須 | タイトルの `id`（`disc.json` の `titles[].id`）。 |
| `titles[].onEnd` | 動作 | 任意 | そのタイトルを最後まで再生したときの動作。 |

- **メニューの識別子**は、英数字・`-`・`_` だけの 1〜64 文字でなければならない（フォルダ名になるため）。
- `titles` に無いタイトル、または `onEnd` の無いタイトルが終わったときは、`firstPlay` がメニューを出す動作なら
  そのメニューを出し、そうでなければ再生を終える。

## 24. MENU/<menuId>/menu.json

```json
{
  "id": "main",
  "canvas": { "width": 1920, "height": 1080 },
  "background": { "video": "bg.mkv", "loop": true },
  "defaultButton": "play",
  "rememberSelection": true,
  "timeout": { "afterMs": 60000, "action": { "playTitle": { "title": 1 } } },
  "buttons": [
    { "id": "play", "rect": { "x": 760, "y": 820, "w": 400, "h": 80 },
      "images": { "normal": "play_n.png", "selected": "play_s.png", "activated": "play_a.png" },
      "nav": { "down": "chapters" },
      "action": { "playTitle": { "title": 1 } } },
    { "id": "chapters", "rect": { "x": 760, "y": 920, "w": 400, "h": 80 },
      "images": { "normal": "ch_n.png", "selected": "ch_s.png" },
      "nav": { "up": "play" },
      "action": { "showMenu": "chapters" } }
  ]
}
```

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `id` | 文字列 | 必須 | メニューの識別子。フォルダ名と同じでなければならない。 |
| `canvas` | オブジェクト | 必須 | 座標系の大きさ（`width`・`height`、画素）。24.3 節。 |
| `background` | オブジェクト | 必須 | 背景。24.1 節。 |
| `audio` | オブジェクト | 任意 | 背景の音声（BGM）。24.1 節。 |
| `defaultButton` | 文字列 | 任意 | 最初に選ばれているボタンの `id`。無ければ先頭のボタン。 |
| `rememberSelection` | 真偽 | 任意 | 真なら、このメニューへ戻ったとき、前に選んでいたボタンを選び直す。既定は偽。 |
| `timeout` | オブジェクト | 任意 | 操作が無いまま `afterMs`（ミリ秒）たったときの動作 `action`。 |
| `buttons` | 配列 | 必須 | ボタン（24.2 節）。空でもよい。 |

ファイル名（背景・音声・ボタンの画像）は、すべて `MENU/<menuId>/` からの相対名で、フォルダを含めてはならない。

### 24.1 背景と音声

- `background` は、`image`（静止画のファイル名）と `video`（動画のファイル名）の**どちらか一方だけ**を持たなければならない。
  - `image`：**PNG** でなければならない（どの読み手でも同じに復号できるように）。
  - `video`：Matroska（映像はタイトルと同じコーデックの規則。音声があれば BGM として鳴らす）。`loop` が真なら、
    最後まで再生したら最初から繰り返す。偽なら最後の絵のまま止める。
- `audio`：`{ "file": "bgm.mka", "loop": true }`。背景が静止画のときの BGM（Matroska の音声）。`loop` が真なら繰り返す。
  背景が動画のとき、読み手は `audio` を使わなくてよい（動画の中の音声を鳴らす）。

### 24.2 ボタン

| キー | 型 | 必須 | 意味 |
|---|---|---|---|
| `id` | 文字列 | 必須 | メニューの中で一意の識別子。 |
| `rect` | オブジェクト | 必須 | 範囲（`x`・`y`・`w`・`h`。canvas の座標）。canvas の中に収まらなければならない。マウス・タッチの当たり判定と、画像を描く範囲。 |
| `images.normal` | 文字列 | 任意 | 選ばれていないときの画像。 |
| `images.selected` | 文字列 | 任意 | 選ばれているときの画像。 |
| `images.activated` | 文字列 | 任意 | 押した瞬間に短く出す画像。 |
| `nav.up`・`nav.down`・`nav.left`・`nav.right` | 文字列 | 任意 | その方向へ移ったときに選ぶボタンの `id`。無い方向へは動かない。 |
| `action` | 動作 | 必須 | 押したときの動作（25 章）。 |

- 画像は **PNG**（透明度あり）でなければならない。読み手は `rect` の大きさへ拡大縮小して背景に重ねる。
- 画像の無い状態では、何も重ねない（背景に図柄を描き込み、選ばれているときの枠だけを重ねる、という作り方もできる）。
- **文字は書き手が画像にして入れる**。読み手はボタンの文字を描かない（どの読み手でも同じ見え方になる）。
- 選ばれているときの効果は画像だけで表す（色・太さなどの指定は持たない）。

### 24.3 座標と表示

読み手は、canvas 全体を映像の表示範囲（背景の表示範囲）へ拡大縮小して重ねる。メニューの表示の縦横比は canvas の
縦横比である。背景の画像・動画の画素数は canvas と違ってよい（canvas の大きさへ拡大縮小する）。

## 25. 動作（action）

動作は、次の**どれか 1 つのキーだけ**を持つオブジェクトで書く。

| 動作 | 意味 |
|---|---|
| `{ "playTitle": { "title": 1 } }` | タイトルを最初から再生する。 |
| `{ "playTitle": { "title": 1, "chapter": 3 } }` | タイトルを指定した章（1 始まり）から再生する。 |
| `{ "showMenu": "chapters" }` | メニューを出す。 |
| `{ "resume": {} }` | メニューを出す前に再生していたタイトルの位置へ戻る（音声・字幕の選択も戻す）。戻る位置が無ければ何もしない。 |
| `{ "setAudio": 2 }` | 音声を選ぶ（`title.json` の `audio[].number`）。メニューは出したまま。以後に再生するタイトルに当てる。 |
| `{ "setSubtitle": 1 }` | 字幕を選ぶ（`title.json` の `subtitle[].number`。0＝字幕なし）。メニューは出したまま。以後に再生するタイトルに当てる。 |
| `{ "stop": {} }` | 再生を終える。 |

- 書き手は、キーを 2 つ以上持つ動作を書いてはならない。読み手は、知っているキーを 2 つ以上持つ動作と、知らないキー
  だけの動作を、**何もしない動作**として扱わなければならない（将来、動作を足すときは新しいキーで足す）。
- `setAudio`・`setSubtitle` の番号が、再生するタイトルに無ければ、読み手はその指定を無視する。

## 26. 再生器の動き

- **始まり**：コントローラに従う再生では、`firstPlay` を実行する（無ければ先頭のタイトルを再生する）。
  前回の再生位置から再開するときは、`firstPlay` を実行せずにその位置から再生してよい。
- **メニューの選択**：メニューを出したときに選ぶボタンは、`rememberSelection` が真で前に選んでいたボタンがあればそれ、
  無ければ `defaultButton`、それも無ければ先頭のボタン。背景のループで出し直すときは、選択を変えない。
- **操作**：上下左右のキーで `nav` に従って選択を移し、決定で `action` を実行する。マウスは、ボタンの上へ来たら選び、
  クリックで実行する。タッチはタップで実行する。
- **押した瞬間**：`images.activated` があれば、それを短い間（目安 0.1〜0.2 秒）出してから動作を実行する。
- **時間切れ**：`timeout` のあるメニューでは、メニューを出してから（または最後に操作してから）操作の無い時間を数え、
  `afterMs` に達したら `timeout.action` を実行する。一時停止中は数えなくてよい。
- **続きから**：タイトルの再生中にメニューを出したとき（再生器のメニューキー・タイトル中の動作による）、読み手は
  その位置と音声・字幕の選択を覚えておき、`resume` でそこへ戻る。別のタイトルを再生したら、覚えた位置は捨てる。
- **タイトルの終わり**：23 章の `onEnd` の決まりに従う。
- **再生器のメニューキー**：タイトルの再生中に押されたら、`keys` のメニューを出す（「続きから」の位置を覚える）。

## 27. 書き手の決まり

書き手は、次を満たさなければならない。読み手は、満たさないファイルに出会ったら、その部分を無視してよい
（例：無いメニューを指す動作は何もしない）。

- `nav.json` の `menus` の各識別子に `MENU/<menuId>/menu.json` があり、その `id` が識別子と同じ。
- 動作が指すタイトル（`playTitle.title`・`titles[].title`）とメニュー（`showMenu`・`keys`）が存在する。
- ボタンの `id` がメニューの中で一意で、`nav`・`defaultButton` が存在するボタンを指す。
- ボタンの `rect` が canvas の中に収まり、幅と高さが正。
- `background` が `image` と `video` のどちらか一方だけを持つ。画像（背景・ボタン）は PNG。
- ファイル名がフォルダを含まず、指すファイルが `MENU/<menuId>/` にある。

# 付録

## 付録 A　実装の注意（参考）

### A.1 デコーダが抱えるフレーム

- H.264・H.265 などのデコーダは、並べ替えのためにフレームを抱え、次の入力が来るまで出さないことがある。
  **流れが終わる所**（静止パーツ・メニューの映像の終わり・ファイルの終わり）では、デコーダから抱えたフレームを
  取り出す（ドレインする）必要がある。ドレインしたデコーダへさらに入力するのは不安定なことがあるので、作り直すのが確実である。
- デインターレースの時間フィルタ（yadif など）も、次のフレームが来るまで最後の 1 枚を出さない。流れが終わる所では、
  フィルタからも抱えたフレームを正しい時刻のまま取り出してから捨てる。取り出さずに捨てると最後の 1 枚が欠け、
  捨てずに次の流れへ続けると、古い絵が混ざる。

### A.2 パーツの境目

- `"dual"` のパーツから全高のパーツへ移るときは、ボトムのトラックのデコーダもドレインしてから、トップと組み合わせる段を
  締める（ボトムは全高の区間に入力が無いので、最後のフィールドが残る）。
- `interlacedRanges` の終わりは、半フィールドぶん内側で判定するとよい（区間の終わりは最後のフレームの表示の終わりなので、
  次のパーツの先頭のフレームの時刻を 1 ms 未満だけ超えることがある）。

### A.3 音声の欠けと無音の補填

- 多くの音声の出力は、PCM を時刻に関係なく詰めて鳴らす。供給が時刻の上で途切れると、以降がその分だけ前へずれて積み重なる。
  同じセグメントの中で次の音声の時刻が「ここまで積んだ終わり」より先なら、その差を**無音で埋める**とよい。
- 書き手は、パーツの音声を「**そのパーツの表示の長さ**」で切り出すべきである。ソフトテレシネでは、元の素材の時刻と
  フィールドを積み上げた時刻がずれるので、元の素材の時刻で切ると 1 フィールドぶん足りなくなることがある。

### A.4 音声の構成の切り替わり

- 再生器は、提示時刻の属するスパンが**前と変わったか**で音声の選択肢を作り直すとよい。シークのときは「今のスパン」を
  未確定に戻し、最初のフレームを提示した時点で作り直す（先回りして書き換えると、変化を見逃す）。

## 付録 B　取り込みの指針（参考）

### B.1 DVD-Video から

- **静止画のセル**：セルごとに「IFO のセルの長さ ＞ 映像の実際の長さ＋1 秒」なら静止画のセルとみなし、静止パーツにする。
  映像の実際の長さは、**RFF を含めた実際のフィールド数×フィールドの周期**で測る（フレーム数×2 で概算すると、
  3:2 プルダウンの普通のセルまで静止画と誤る）。
- **インターリーブブロック**：物理的に交互に並んだ枝は、ナビゲーションの情報（VOB_ID・Cell_ID）で当該の枝だけを取り出す。
- **字幕**：各物理サブストリーム（表示モード別）のサブピクチャを、表示の単位ごとに生のまま `.spu` として書く。
  表示の始まり・終わりを cue の `startMs`・`endMs` に写す。表示中の変化はサブピクチャの中にあるので展開しない。
- **音声のラウドネス**：AC-3 の `dialnorm` を `dialogLevelDb`、各ブロックの `dynrng` を `drc`、`compr` を `drcRf` に写す。
  DTS はコアヘッダの会話音量のゲインを `dialogGainDb`、埋め込みの DRC 係数を `drc` に写す。LPCM・MPEG 音声には無い。
- **アングル**：全アングルを物理どおりに格納する（同じ映像でも畳まない）。

### B.2 Blu-ray から

- **字幕（PGS）**：復号しない。セグメントの並びをたどって表示の始まりと消去（オブジェクト数 0 の構成）だけを判定し、
  表示を始める Display Set から消去の直前までのバイト列をそのまま `.pgs` に書く。
- **アングル**：同じ PlayItem の各アングルの長さと構成が等しいことを確かめて `angleType: "bd"` にする。

### B.3 放送の MPEG-2 TS から

- **サービス＝タイトル**：選べるサービスごとに 1 タイトル（同じ映像を指すものは 1 つにまとめる）。
- **番組＝`events[]`**：番組が切り替わってもセグメントを分けず、時刻付きの `events` で表す。
- **音声・映像の時間の変化**（デュアルモノ⇔ステレオ、インターレース⇔フィルム）も分けず、スパンや区間で表す。
  セグメントを分けるのは、1 本の符号化ストリームに収まらない変化（解像度・縦横比・コーデック、音声のチャンネル数）だけ。
- **字幕（ARIB）**：テキスト型（`charset: "arib"`）にする。`source` は字幕の PID（2 言語目は PID＋0x10000）。
